# 织境 Loomscape

一个面向创作者的多模态工作台：文字、画面、声音与时间放在同一个工作面里，从一句提纲起稿，在同一个地方收尾。

仓库当前是 v0.3，两页式结构——第一页横向翻阅产品介绍，继续向下滚动吸附到第二页：完整的工作台。两页在同一个文档里，数据默认只写进浏览器，不经过服务端。

## 现在能做什么

| 工作台 | 已实现 | 需要外部服务 |
| --- | --- | --- |
| 文本 | 流式起草、工具调用（语气规则/字数测量/标题备选）、中断续写、归档、记忆召回；引擎跟随设置 | 是（未配置时给结构草案） |
| 对话 | 多轮流式问答（带上下文历史）、知识库入库与检索、引用编号与来源列表、关闭检索的纯对话 | 是（未配置时给检索结果） |
| 图像 | 提示词出图、比例与数量、批量结果、下载与归档 | 否（未配置时本地程序化构图） |
| 影像 | 导入源片、播放走查、时间线裁切、拆分排序、导出片段清单 | 否 |
| 声音 | 浏览器录音、实时波形、转写校对、浏览器朗读（TTS）、语速与音色 | 转写需要 |
| 故事 | 分镜编排、挂接归档画面、Markdown 导出、存为作品 | 否 |
| 社交 | UID 通讯录、群组、群公告、消息收发与未读红点（同设备多标签通过 BroadcastChannel） | 否 |
| 设置 | 引擎选择（云端/本地）、模型下载与进度、四类端点、记忆管理、数据导出与清空 | — |

未配置端点时，文本工作台输出的是**结构草案**（立意、骨架、语气备选），不是伪造的模型结果——界面会明确标注；对话工作台则只给检索到的片段，同样标注 `retrieval only`。

## 引擎：云端与端侧

文本和嵌入各有两条路径，在设置页切换：

- **云端**：OpenAI、Anthropic Claude、Google Gemini、智谱 AI、DeepSeek，或任何兼容端点。各家用各自的协议（OpenAI 与 GLM、DeepSeek 走 chat completions，Claude 走 Messages API，Gemini 走 Generative Language API），由服务端按 `wire` 选择对应 SDK provider。
- **本地**：权重通过 transformers.js 在浏览器内运行，下载后断网可用。

体积按仓库里真实文件计，两列对应两种后端：

| 模型 | 任务 | WASM（int8） | WebGPU（fp16） | 说明 |
| --- | --- | --- | --- | --- |
| Qwen3 0.6B | 文本 | 589 MB | 1.12 GB | 默认档，单次限 240 token；问答与摘要可用，长句改写仍会跑偏 |
| BGE Small 中文 | 嵌入 | 23 MB | 45 MB | 512 维，中文短句够用，冷启动最快 |
| BGE Base 中文 | 嵌入 | 98 MB | 194 MB | 768 维，中文检索明显好于 Small，仍是百兆级 |
| BGE-M3 | 嵌入 | 543 MB | 1.06 GB | 1024 维，多语长文本，质量最好 |

WebGPU 一列不是「想要就有」：它要求仓库里有一份**单文件**的 `model_fp16.onnx`。fp16 若被拆成「小结构图 + 几 GB 外置数据」，浏览器没法把它塞进一个 `ArrayBuffer`，那一档就只剩 int8。

**文本只留 0.6B 一档，1.7B 试过但撤了。** Qwen3 1.7B 的 int8 权重 1.62GB，下载完成、创建会话时渲染进程涨到 4.1GB，onnxruntime 直接在 wasm 堆上 `Aborted()`；页面重载后卡片退回「未加载」，看起来像什么都没发生。浏览器里超过 1GB 的 int8 解码器基本都会撞这个 4GB 上限，所以质量档交给云端，而不是摆一个点开就崩的选项。这次实测也顺手改掉了「崩了没提示」：加载前写一条 localStorage 标记，正常结束才清除，下次进设置页若还留着，就在那张卡片上报「上次加载被中断」。

> 0.5B 时代的两份权重（Qwen2.5 0.5B、E5 Small 多语）已从目录撤下，但缓存在本机的文件还在。设置页底部会单独列出「旧版模型权重」并给一个清理入口——卡片删掉了，空间也得能收回来。

下载源可切 **阿里 ModelScope**（国内直连）与 **HuggingFace**（官方）；两者使用同一份文件路径规则，切换后需要重新下载。下载过程有按文件的进度与字节数显示，权重存在浏览器 Cache Storage，可在设置页删除。

**端侧有两条不同的提示词**。云端用完整的创作助理设定；本地模型换成一句短提示（`COMPACT_PROMPT`）。这不是偷懒：端侧模型的上下文预算很小，一段人格设定会把注意力吃光，实测同一句话在长提示下答成「这是除法」，短提示下能给出正确结果。

**纯算式不走模型**。`10-3是多少`、`7乘以8` 这类完全确定的输入由 `lib/arithmetic.ts` 直接算，回答标注 `calculator`；句子形式的请求（「帮我把 10-3 写成文案」）不会被抢走，仍然交给模型。端侧小模型会把 `10-3` 读成 `10.3`，这类错误不该用采样来赌。

**思考块不外露**。Qwen3 是混合推理模型，即使提示词里已经塞了一个闭合的 think 块，它也可能自己再开一个。`local-runtime` 的流式过滤器在 token 到达时就丢掉 `<think>...</think>`，而不是等整段生成完再正则：否则推理过程会先闪出来，再被替换掉。提示词侧的 `prefill` 与过滤器是两道独立的闸。

**加载即选用**。本地模型区给每个模型一个「加载」入口，加载完成就同时写入对应引擎的偏好，不再单独设「当前模型」。状态只有两种说法：权重在盘上叫**已下载**（带实际占用），在内存里叫**已加载**。面板顶部有一行状态：哪个模型在内存里、用的什么后端、几个线程。模型按文本/嵌入分组，标题取代了原先每张卡上的任务角标。

**进工作台自动加载**。设置里选的是本地引擎、权重又已经下载时，进入工作台（含刷新后）会自动把它加载进内存，不用再点一次；只加载已下载的权重，不会因为滚动到工作台就悄悄起一个几百兆的下载。加载过程在顶栏右侧显示百分比，顶栏底边有一条进度线。

**缓存判定看权重文件**。只缓存了 config 或 tokenizer 不算就绪，必须是当前后端对应的那个 `.onnx`：WASM 看 `model_quantized.onnx`，WebGPU 看 `model_fp16.onnx`。否则半途中断的下载会显示成「已缓存」，下次加载才在缺文件的地方失败。只下了另一种精度时标成「已下载 int8 / fp16 权重」，换后端即可用；两种都没有、但有别的文件（例如旧版本的 fp32）标成「旧权重」，可以直接清理。失败时该行会显示真实原因，并提供「重试」「删除缓存并重试」——残缺的权重只有删掉重下才能修好。

**下载前先看空间**。模型区会显示本机存储已用/配额；开始下载前用 `navigator.storage.estimate()` 预检，剩余空间不够就直接说明「已用多少 / 配额多少 / 还差多少」，而不是让浏览器在写缓存时抛一个只有一个数字的底层中断再显示出来。

**同一时间只驻留一个**。加载第二个会先释放第一个的 ONNX session 与权重引用，再开始加载；连续点几个也只会留下最后一个，因为加载是串行的——两个加载并行时先完成的那个会被后来者悄悄留在内存里。因为一对一，加载文本模型会把嵌入引擎切回哈希，反之亦然。

**WASM 多线程**。嵌入模型取 `hardwareConcurrency - 1`、上限 4；文本模型上限 **2**——解码要一直持有 KV cache 和每线程的 arena，4 线程换来的速度抵不上多出来的内存。WASM 线程依赖 `SharedArrayBuffer`，而它只在跨源隔离的文档里存在，所以应用对所有路由下发 `Cross-Origin-Opener-Policy: same-origin` 与 `Cross-Origin-Embedder-Policy: credentialless`；`credentialless` 而不是 `require-corp`，是为了让工作台里的远程图片不需要额外 CORP 头。代理把这些头丢掉时线程数会回落到 1，面板里会注明原因。

**内存**。会话创建时关掉 `enableCpuMemArena` 与 `enableMemPattern`：这两项默认开启，会按图的峰值预分配 planner，正是把标签页推向 4GB 上限的主要原因。实测（0.5B/int8、2 线程）加载后渲染进程约 2.4GB，空闲页约 0.16GB；0.6B 与它同一量级。再往上（1.7B/int8）就是 4.1GB 与 `Aborted()`。

`unloadModel()` 会 `dispose()` 掉 ONNX 会话，但 **WebAssembly 的线性内存无法缩回**，卸载只能释放约 600MB，剩下要等标签页刷新或丢弃才归还系统。所以面板在卸载后会直接说明这一点，并给一个「刷新页面」按钮；设备内存 ≤ 4GB 时也不会在进入工作台时自动加载文本模型，避免一进页面就顶到上限。

后端策略：默认走 **WASM + int8**，体积最小、兼容性最好。选择 **WebGPU** 时用 **fp16**，不是 fp32——这些仓库的 fp32 权重是「0.6MB 计算图 + 2.1GB 外置数据」，下载量翻倍，而且 2.1GB 已经超过浏览器能塞进一个 `Response` 的上限（`RangeError: ArrayBufferView size exceeds the supported range`）。浏览器没有适配器时自动回落到 WASM。

卡片上标的体积跟着后端走：切到 WebGPU 会显示 fp16 的数字，并按这个数字做存储预检。

## 检索增强（RAG）

对话工作台把「知识库」当作上下文来源，链路很短，每一环都能在界面上看到：

1. 粘贴一段资料入库，按段落切成带重叠的分块，逐块向量化后写进 IndexedDB；每块记着 `docId / 片段序号 / 总段数`。
2. 提问时先嵌入问题，与同一嵌入空间的分块算余弦相似度，取前 4 条；相似度低于 **0.2** 的直接丢掉。阈值原来是 0.12，实测「10-3是多少」能以 0.144 命中一条拍摄参数笔记，模型于是照着笔记作答。
3. 命中片段拼成带编号的上下文交给模型，要求它在句末标注 `[n]`；**没有命中时不拼接、也不提「片段」**，否则模型会对着空上下文编引用。
4. 回答下方的来源列表按编号排开；**被引用的一条保持深色，没被引用的淡出**，避免「检索到了但没用」被误读成有据可依。

嵌入引擎的三档（哈希 / 本地 BGE / API）在设置里切换。哈希兜底零依赖、毫秒级，代价是只能用字面重合度；换成 BGE 后同义改写也能命中。两种向量空间不互通，记录带 `embedder` 标签，切换后旧片段自动退出召回。

**检索只吃资料，不吃自己的回答**。助手说过的话会作为 `note` 记忆留给「设置 → 记忆」，但对话检索的 `kinds` 只包含 `doc / text / story / voice`：把上一条回答当成检索片段喂回去，模型会顺着复述自己，读起来就是「重复」。同理，本地路径会把最近 6 轮对话拼进提示词，否则追问会变成没有上下文的新问题。

对话本身不落盘：只有显式入库的资料、以及助手给出过的回答（作为 `note` 记忆）会留在本地。需要留档的草稿在文本台点「保存」进作品库。

## 快速开始

```bash
npm install
cp .env.example .env.local   # 可选，也可以直接在设置页里填
npm run dev
```

打开 <http://localhost:3000>。Node 18.17 以上。

生产构建：

```bash
npm run build
npm start
```

测试：

```bash
npm test          # vitest：数据层与迁移、RAG、端点预设、SSRF 拦截、线程数计算
npm run test:e2e  # playwright：首屏骨架、吸附、导航、端点保存、跨源隔离、模型驻留、对话检索、移动端
```

`test:e2e` 需要先 `npm run build`，会拉起 `next start` 并用本机 Edge 跑一遍；也可用 `E2E_BASE` 指向已经在跑的服务。

## 配置生成服务

两种方式，任选其一：

1. **在界面里配置**（推荐）：`/studio/settings` → 端点与模型 → 填 Base URL、模型、API Key → 保存。配置写在浏览器 IndexedDB，请求时随请求体转发，服务端不落盘。
2. **服务端环境变量**：复制 `.env.example` 为 `.env.local`，填 `OPENAI_*` / `IMAGE_*` / `SPEECH_*`。这样同一部署下的所有访问者共享一套凭据，适合内网或个人部署。

支持的协议：

- 文本：OpenAI、Anthropic Claude、Google Gemini、智谱 GLM、DeepSeek，或任何兼容 `POST /chat/completions` 的自建服务
- 嵌入：任何兼容 `POST /embeddings` 的服务（通义 text-embedding-v3/v4、OpenAI text-embedding-3-*）
- 图像：OpenAI `POST /images/generations`、Stability `POST /v2beta/stable-image/generate/sd3`
- 语音：Whisper 兼容 `POST /audio/transcriptions`

`/api/chat` 会把上游的 SSE 转成统一的 `delta` 事件，浏览器端只解析一种格式。

## 几点设计说明

**拟态与纸面**。整体是浅色立体（neumorphism）：同一色相上做明暗双向投影，按下去阴影翻转为内凹。没有纯白卡片，也没有硬边框，层次靠光影而不是描边。

**织纹背景**。首页背景是一块用顶点着色器变形的线阵，44 条经线与 26 条纬线，鼠标位置会轻微把它拽向光标。用 three.js 手写，不引 R3F，首屏 JS 控制在 90KB 左右（gzip 前）。

**两页之间**。介绍页是 `overflow-x` 的吸附容器，外面再套一层 `overflow-y` 吸附容器。在第 4 屏继续向下滚时，滚轮事件不再被横向容器拦截，交给文档吸附到工作台；在工作台顶部继续向上滚，`overscroll` 会链回介绍页。`/studio` 重定向到 `/#workspace`，直接分享链接也能落到工作台。

**纸飞机**。位置由横向翻阅的滚动进度驱动，沿左下的起点飞到右上，末屏缩小消失。用 `left/top` 百分比而不是位移百分比——后者以元素自身尺寸为基准，会在窗口变化时跑偏。

**记忆**。不引入向量数据库，余弦相似度内存里算。嵌入有三档：哈希 n-gram（零依赖兜底）、本地模型（BGE Small / Base / M3，端侧推理）、API（通义 / OpenAI）。不同引擎的向量空间不互通，记录里带 `embedder` 标记，切换后旧片段自动退出召回，不会拿两种向量硬比。批量入库时如果编码器只返回了一部分向量，整批退回哈希并改标签，不让两种向量混进同一个索引。

**身份是显式的**。首次进入自动建立访客身份，但退出登录会写一个 `loomscape:signed-out` 标记：刷新后仍是未登录，工作台里直接给出「登录 / 注册」与「以访客身份继续」，不再偷偷生成一个新访客。顶栏对访客也保留登录入口——访客升级成账户需要它。

**访客不写 email 字段**。`users` 对 `email` 建了唯一索引，而访客没有邮箱；早期给访客写 `email: ''`，于是**第二个访客必然撞唯一约束**（`ConstraintError`），界面只能报「无法创建访客会话」。现在访客记录干脆不带这个键——IndexedDB 对缺少索引键的记录不做索引，也就不会冲突。

**弹窗自己管卸载**。`AnimatePresence` 曾在「关闭的同时父组件树发生变化」（登录成功就是）时卡住：面板淡到 `opacity: 0` 却一直挂着，留一层 `pointer-events: auto` 的全屏遮罩把所有点击吃掉。现在卸载由定时器兜底，遮罩在关闭态一律 `pointer-events-none`。同一个 effect 还负责关闭时的焦点回收，所以输入框不会在每次按键后被挪到关闭按钮上。

**未读是水位线，不是计数器**。`seenAt[会话]` 记到哪一刻算已读，红点数由「此刻的库里的消息减去水位」算出来；只靠事件的计数器在刷新、关标签页后必然漂移。打开会话推进水位，群公告用 `updatedAt` 版本单独比较。

**导航分上下两段**。工作台去掉侧栏：顶栏只放品牌、当前位置与账户，切换工作台用底部坞。理由是七个以上入口竖排会挤占正文宽度，而底部是拇指区；介绍页的顶栏+底部翻页也是同一套语言，两屏之间不用换手势。

**数据模式有版本**。`providers` 早期用 `id` 做主键，而端点只有 `channel`，每次保存都会抛 `DataError`。v2 升级时删掉这张空表并按 `channel` 重建；`put()` 先校验主键字段，缺键时报出字段名而不是丢一个原生 DOMException。

**端侧运行时**。transformers.js 与 onnxruntime 不从 CDN 拉，构建时复制进 `public/runtime`，用原生 `import()` 加载——webpack 无法处理 onnxruntime 内部的 `import.meta`。这样首屏不带这个包，只有真正启用本地模型时才加载。

**工具调用**。服务端用 AI SDK 的 `streamText` + `maxSteps: 3`，挂了三个纯函数工具：`style_guide`（语气规则）、`measure`（字数/段落/朗读时长）、`title_variants`（标题备选）。它们没有副作用，因此不需要在客户端回传结果。

**骨架屏**。首次进入的骨架直接写在服务端输出里，第一帧就是骨架而不是半成品页面；字体就绪后淡出，与最终 UI 的宽高严格对齐，避免切换时抖动。骨架只用 CSS 动画，不额外加载脚本。

## 已知边界

- 账号是**本机账户**，没有服务端用户表，换设备不会同步；清空浏览器数据即注销。
- 模型缓存在浏览器 Cache Storage 里，按 origin 隔离：换端口或域名要重新下载。
- 加载状态只活在当前页面：刷新后模型从内存释放，需要在设置里重新点「加载」（权重仍在缓存，不用重新下载）。
- 只驻留一个本地模型，所以「本地文本 + 本地嵌入」不能同时开；换一个会顶掉另一个。
- 跨源隔离要求反向代理保留 COOP/COEP 响应头，否则 WASM 退化为单线程（功能不受影响，只是慢）。
- 本地文本模型（0.6B/int8、2 线程）是每秒十几个 token 的量级，适合短问答与摘要；单次上限 240 token，长文请用云端。本地模式不支持工具调用。
- 端侧模型的算术由本地计算器处理；其余事实、推理与多步任务仍会出错（0.6B 实测同一道常识题两次里有一次答「不确定」），这类问题请切云端。
- 哈希嵌入的字面重合度很低：实测「光线的描述」对一段以「光线」开头的资料只有 0.075 分，会被阈值挡掉。想要语义召回请换 BGE。
- 端侧会话的峰值内存约 2.4GB，且卸载后不会立刻归还（WASM 内存不能收缩）；低内存设备请谨慎加载，必要时刷新页面。
- 实时消息走 BroadcastChannel，限定同一设备的多个标签页。跨设备需要把 `social.ts` 的传输层换成 WebSocket。
- 访客期间产生的作品与记忆挂在访客身份下，注册或登录后不会自动迁移。
- 未读数按本机水位线计算；换设备或清空站点数据后，历史消息会被当作已读。
- 对话记录只存在于当前标签页；刷新即清空，记忆与作品库不受影响。
- 端侧模型仍有明显的能力上限：0.6B 常把一句写成一段、长句改写会跑题。想要更强的本地模型得走 WebGPU + 4-bit 权重（`model_q4f16.onnx`），这一版还没做，因为本机只能在 WASM 下验证，而 WASM 撑不住 1B 以上。工具调用只有云端支持。
- 哈希嵌入只看字面重合，问法与资料用词差得远时会检索不到；换成 BGE 才有语义召回。
- 影像只做工程层：记录片段区间并导出 JSON，不做服务端转码与合片。
- 社交没有服务端 UID 校验，任何符合格式的 UID 都能加进通讯录。
- 群公告只有一个版本，没有历史记录；同一设备多标签之外的人看不到。
- `/api/*` 是转发路由：部署在公网时请为你的域名设置 `ALLOWED_ORIGINS`，并注意它只做内网地址拦截，不做限流。
